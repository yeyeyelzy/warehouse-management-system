## 1. 通用约定

### 1.1 交互方式

- 页面接口为**表单提交 + 服务端跳转**模式：`POST` 处理后 `redirect` 回原页面，通过 `RedirectAttributes.addFlashAttribute` 传递一次性提示消息。
- 提示消息三类：`success`（成功，绿色）、`error`（失败，红色）、`warning`（库存预警，黄色）。
- 所有涉及库存变动的接口，最终一致性由数据库存储过程 / 触发器保证，接口只负责传参与展示结果。

### 1.2 返回码约定（存储过程 OUT 参数）

| status_code | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 失败（存储过程已 ROLLBACK） |
| null | 调用异常（按失败处理，提示「业务处理失败」） |

### 1.3 认证约定

除 `/login`、`/css/**`、`/js/**`、`/error` 外，其余路径均由 `AuthInterceptor` 拦截，未登录（Session 无 `loginUser`）跳转 `/login`。角色级权限由成员 A 补充。

密码安全：用户密码以 **SHA-256 加盐密文**（`salt:hash`）存储，登录时由 `PasswordUtil.matches()` 做散列比较，不做明文比对；演示账号明文统一为 `123456`，登录接口参数不变。

## 3. 核心业务接口详细说明（B 主责）

### 3.1 采购入库

- **页面**：GET `/biz/inbound` → 返回 `inbound` 页面，注入下拉数据 `warehouses` / `goodsList` / `suppliers`。
- **提交**：POST `/biz/inbound`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| warehouseId | Integer | 是 | 入库仓库编号 |
| goodsId | Integer | 是 | 货品编号 |
| quantity | BigDecimal | 是 | 入库数量（>0） |
| unitPrice | BigDecimal | 是 | 入库单价（>=0） |
| supplierId | Integer | 否 | 供应商编号 |
| （Session）loginUser | SysUser | 是 | 取 operatorId |

- **成功**：`success="采购入库成功"`（底层 `sp_inbound`，biz_type=PURCHASE），随后按库存状态追加 `warning`。
- **失败示例**：

| 输入 | 返回 |
| --- | --- |
| quantity=0 | error=「入库数量必须大于0」 |
| 未选仓库 | error=「入库仓库不能为空」 |
| unitPrice=-1 | error=「入库单价不能为负」 |

### 3.2 销售出库（FIFO / LIFO）

- **页面**：GET `/biz/outbound`
- **提交**：POST `/biz/outbound`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| warehouseId | Integer | 是 | 出库仓库编号 |
| goodsId | Integer | 是 | 货品编号 |
| quantity | BigDecimal | 是 | 出库数量（>0） |

- **成功**：`success="销售出库成功，出库成本 = 620.00"`（`outTotalCost` 来自存储过程）。
- **失败示例**：

| 输入 | 返回 |
| --- | --- |
| quantity 超库存 | error=「库存不足，无法出库」（库存不变） |
| quantity=0 | error=「出库数量必须大于0」 |

### 3.3 领料出库

- **页面**：GET `/biz/materialIssue`
- **提交**：POST `/biz/materialIssue`，参数同销售出库（底层 `sp_outbound_cost`，biz_type=MATERIAL_ISSUE）。
- **成功**：`success="领料出库成功，出库成本 = <cost>"`（B-04 已补充成本展示）。
- **失败**：同销售出库。

### 3.4 回料入库

- **提交**：POST `/biz/materialReturn`，参数同采购入库（底层 `sp_inbound`，biz_type=MATERIAL_RETURN，`supplierId` 传 null）。
- **成功**：`success="回料入库成功"`；失败同采购入库。

### 3.5 退货处理

- **提交**：POST `/biz/return`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| warehouseId | Integer | 是 | 仓库编号 |
| goodsId | Integer | 是 | 货品编号 |
| quantity | BigDecimal | 是 | 数量（>0） |
| returnType | String | 是 | PURCHASE_RETURN（采购退货出库）/ 其它（销售退货入库） |
| unitPrice | BigDecimal | 否 | 仅销售退货入库使用 |

- **成功**：采购退货 → `success="采购退货出库成功，出库成本 = <cost>"`；销售退货 → `success="销售退货入库成功"`。

## 5. 存储过程契约（与 C 联合确认）

> 本表是 B 与 C 的联调契约：B 按此传参、读取状态，C 保证实现一致。

### 5.1 sp_inbound

| 方向 | 参数 | 类型 | 说明 |
| --- | --- | --- | --- |
| IN | p_warehouse_id | INT | 入库仓库 |
| IN | p_goods_id | INT | 货品 |
| IN | p_quantity | DECIMAL | 数量（>0） |
| IN | p_unit_price | DECIMAL | 单价 |
| IN | p_operator_id | INT | 操作人 |
| IN | p_supplier_id | INT | 供应商（可 NULL） |
| IN | p_biz_type | VARCHAR | PURCHASE / SALE_RETURN / MATERIAL_RETURN |
| OUT | p_status_code | INT | 0 成功 / 1 失败 |
| OUT | p_status_msg | VARCHAR | 结果消息 |

### 5.2 sp_outbound_cost

| 方向 | 参数 | 类型 | 说明 |
| --- | --- | --- | --- |
| IN | p_warehouse_id | INT | 出库仓库 |
| IN | p_goods_id | INT | 货品 |
| IN | p_quantity | DECIMAL | 数量（>0） |
| IN | p_operator_id | INT | 操作人 |
| IN | p_biz_type | VARCHAR | SALE / MATERIAL_ISSUE / PURCHASE_RETURN |
| OUT | p_status_code | INT | 0 成功 / 1 失败 |
| OUT | p_status_msg | VARCHAR | 结果消息 |
| OUT | p_out_total_cost | DECIMAL | 本次出库核算总成本 |

### 5.3 sp_stocktake（C 主责）

| 方向 | 参数 | 说明 |
| --- | --- | --- |
| IN | p_warehouse_id / p_goods_id / p_actual_quantity / p_operator_id | 盘点仓库、货品、实盘数量（>=0）、操作人 |
| OUT | p_status_code / p_status_msg | 0 成功 / 1 失败 |

### 5.4 sp_transfer（C 主责）

| 方向 | 参数 | 说明 |
| --- | --- | --- |
| IN | p_from_warehouse_id / p_to_warehouse_id / p_operator_id / p_items | 调出仓、调入仓、操作人、明细 JSON |
| OUT | p_status_code / p_status_msg | 0 成功 / 1 失败 |

## 6. 错误码汇总表

| 错误码 | 来源 | 消息 | 触发条件 |
| --- | --- | --- | --- |
| SVC-001 | Service | 入库仓库不能为空 | warehouseId 为空 |
| SVC-002 | Service | 货品不能为空 | goodsId 为空 |
| SVC-003 | Service | 入库数量必须大于0 | quantity <= 0 |
| SVC-004 | Service | 入库单价不能为负 | unitPrice < 0 |
| SVC-005 | Service | 出库仓库不能为空 | warehouseId 为空 |
| SVC-006 | Service | 出库数量必须大于0 | quantity <= 0 |
| SP-001 | sp_inbound | 入库数量必须大于0 | 数量 <= 0 |
| SP-002 | sp_outbound_cost | 出库数量必须大于0 | 数量 <= 0 |
| SP-003 | sp_outbound_cost | 库存不足，无法出库 | 可用批次合计 < 出库数量 |
| SP-004 | sp_outbound_cost | 成本批次不足，出库核算失败 | 理论兜底分支 |
| SP-005 | sp_stocktake | 实盘数量不能为负 | 实盘 < 0（C） |
| SP-006 | sp_transfer | 源仓库库存不足，无法调拨 | 源仓库存不足（C） |
| SP-007 | sp_transfer | 调出仓库与调入仓库不能相同 | 两仓相同（C） |
| AUTH-001 | AuthService | 用户不存在 | 用户名无匹配记录 |
| AUTH-002 | AuthService | 密码错误 | 密码散列不匹配 |
| SYS-001 | 全局处理器 | 该数据已被其他业务数据引用… | 数据完整性异常 |

> 说明：`SVC-*` 错误码为本文档为追踪而定义的逻辑编号，代码中通过 `BusinessException` 的消息文本体现，未在代码中硬编码编号；如需落地编号，可在 A 的追踪矩阵中映射。
