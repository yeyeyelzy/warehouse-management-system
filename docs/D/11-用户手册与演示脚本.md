# 11-用户手册与演示脚本

> 演示负责人：成员 D<br>
> 适用版本：`main` / `f567731dc08f1869692cb9119dd417446c712f71`

## 1. 初始化与启动

1. 启动本机 MySQL，并确认目标为可重置的隔离实验库；不要在含有他人数据的库执行初始化。
2. 在 `code/src` 的本机运行环境中配置未提交的 `.env`，字段以 `.env.example` 为准；真实凭据不得写入源码、文档或 Git。
3. 在 `code/sql` 依次执行 `01_create_tables.sql`、`02_create_views.sql`、`03_create_triggers.sql`、`04_create_procedures.sql`、`05_test_and_verify.sql`、`08-rbac-lab.sql`。需要完整核对时继续执行 `06_regression.sql`、`07-数据一致性验证.sql`。
4. 在 `code/src` 执行 `mvn spring-boot:run`，访问 `http://127.0.0.1:8080/login`。

## 2. 课堂演示步骤

| 步骤 | 操作 | 预期展示 |
| --- | --- | --- |
| 1 | 未登录访问 `/biz/inbound` | 重定向到登录页 |
| 2 | 用采购角色登录，打开采购入库 | 可访问入库；盘点等受限入口被拒绝 |
| 3 | 提交合法采购入库 | 成功提示；库存与批次增加 |
| 4 | 将数量设为 0 或单价设为负数 | 显示明确错误且不生成业务单据 |
| 5 | 用仓管角色执行销售出库 | 成功消息展示“出库成本 = …”，说明 FIFO/LIFO 由货品计价方式决定 |
| 6 | 执行领料出库或采购退货 | 成功消息同样展示出库成本 |
| 7 | 执行盘点和调拨 | 正常操作成功；负盘点或超库存调拨失败且数据不变 |
| 8 | 用系统管理员访问用户/权限管理 | 可进入管理页面；可说明密码以加盐散列保存 |
| 9 | 退出登录后再次访问受限页面 | 被重新定向到登录页 |
| 10 | 执行 `07-数据一致性验证.sql` | 异常检查返回 0 行 |

## 3. 演示数据恢复

如需恢复干净数据，先确认当前库是隔离实验库，再按第 1 节 SQL 顺序重新构建。初始化会清空该库的业务表，课堂演示之外不得对未知数据库执行。

## 4. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 应用启动后无法登录 | 核对 MySQL 服务与 `.env` 的主机、端口、库名和账号是否对应隔离库；不要记录真实密码 |
| SQL 提示对象已存在 | 确认是隔离库后，从 `01_create_tables.sql` 起重新初始化，不要混用旧脚本 |
| 页面提示无权限 | 使用拥有该业务权限的演示角色；这是角色控制的正常结果 |
| 盘点/调拨/出库失败 | 检查数量与库存；库存不足、负盘点等失败提示可作为异常流程演示 |

## 5. 演示结束检查

关闭应用前执行一次 `07-数据一致性验证.sql`。如结果存在异常，不以“演示成功”替代数据核对，应保留现象并按责任边界反馈 A、B 或 C。

## 6. 可复现演示数据与完整流程

演示前可重建隔离库，或在确认只含演示数据后清空业务表、保留基础资料。以下数据用来直观展示 FIFO/LIFO 和库存联动：仓库 1、仓库 2；G001（FIFO）、G002（LIFO）；库存上下限为 10/1000。

| 步骤 | 输入 | 预期结果与讲解点 |
| --- | --- | --- |
| 1 | 仓库1/G001 入库 `100 × 5.00` | 库存 100、资金 500；`sp_inbound` 和入库触发器联动 |
| 2 | 仓库1/G001 再入库 `50 × 6.00` | 库存 150、资金 800，形成两批成本 |
| 3 | 仓库1/G001 出库 120 | FIFO 成本 620.00，余量 `30 × 6.00` |
| 4 | 仓库1/G002 依次入库 `100 × 5.00`、`50 × 6.00` | 库存 150、资金 800 |
| 5 | 仓库1/G002 出库 120 | LIFO 成本 650.00，余量 `30 × 5.00` |
| 6 | G003 先入库 `30 × 5.00`，再领料出库 10、回料入库 `5 × 4.00` | 演示复用出库/入库过程与业务类型 |
| 7 | G004 先入库 `20 × 5.00`，采购退货 5、销售退货 `8 × 5.00` | 演示采购退货出库和销售退货入库 |
| 8 | 仓库1/G005 实盘 100 | 盘盈（GAIN）并生成盘点记录 |
| 9 | G006 先入库 `20 × 5.00`，实盘 5 | 盘亏（LOSS），低于下限时生成 LOW 预警 |
| 10 | 将仓库1/G001 调拨 10 到仓库2 | 源仓减、目标仓增，两仓合计不变 |
| 11 | 打开库存与预警页 | 对照 `v_stock_overview`、`v_stock_warning` 和 `stock_alert` |
| 12 | 打开报表页 | 展示出入库汇总、供应商供货、盘点盈亏三类统计 |

## 7. 健壮性、易用性与答辩讲解要点

| 场景 | 操作 | 应说明的结果 |
| --- | --- | --- |
| 库存不足 | 对可用库存不足的货品出库 | 提示库存不足，单据、库存、批次均不产生部分写入 |
| 调拨不足 | 调拨数量大于源仓库存 | 源/目标库存和调拨单均不变，事务整体回滚 |
| 负盘点 | 实盘数量为负 | 被拒绝，不产生库存修正 |
| 非法入库 | 数量为 0 或单价为负 | 显示明确提示，无业务单据写入 |

答辩时可按“业务逻辑下沉 MySQL；4 个存储过程负责原子业务；触发器维护库存和预警；Java 负责权限、参数、调用与提示；D 用页面、测试和一致性核对保证可演示性”的顺序说明。页面的下拉选择、成功/失败提示、预警标签和表格报表可作为易用性证据。
