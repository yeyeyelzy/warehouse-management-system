# 成员 D 两阶段测试执行方案

> 适用角色：成员 D（前端开发工程师、测试工程师、演示负责人）<br>
> 项目：仓库管理系统<br>
> 外部截止日：2026 年 11 月 25 日<br>
> 内部冻结时间：2026 年 11 月 24 日 22:00<br>
> 阶段划分依据：是否已经收到成员 B 的冻结产物和明确待测版本<br>
> 用途：本文件可直接作为 Agent 的执行指令。Agent 应按顺序完成任务、生成规定文档并保存测试证据，不得用推测代替实际测试。

---

## 1. D 的职责边界

成员 D 只负责以下内容：

1. 梳理登录、入库、出库、盘点、调拨、库存查询和预警的页面流程；
2. 制定测试计划和测试用例；
3. 执行基线测试、功能测试、异常测试、权限测试、集成测试和回归测试；
4. 记录缺陷、分派问题并复测；
5. 在确有必要时修复表单校验、页面提示、按钮可见性等小范围前端问题；
6. 编写最终测试报告、用户手册和演示脚本；
7. 对最终冻结版本给出“通过 / 有条件通过 / 不通过”的测试结论。

成员 D 不负责：

- 重写 Controller、Service、Mapper 或存储过程；
- 修改库存、批次和流水的一致性规则；
- 擅自改变需求或角色权限边界；
- 在没有测试证据时把功能标记为“通过”；
- 在真实 `.env`、密码或其他敏感配置中截图或写入报告；
- 未经 C 确认直接执行会清空业务数据的 SQL 脚本。

问题分流规则：

| 问题类型 | D 应反馈给谁 |
|---|---|
| Controller、Service、接口参数、业务规则、后端错误提示 | B |
| 库存、批次、触发器、存储过程、事务回滚、数据不一致 | C |
| 权限规则、验收标准或需求含义不明确 | A |
| 页面表单、前端校验、展示、跳转、按钮状态 | D 自行处理 |

---

## 2. 两阶段总流程

```text
阶段一：收到 B 冻结产物前
  ↓
阅读需求与现有文档
  ↓
记录当前代码版本
  ↓
完成构建检查、页面走查和基线测试
  ↓
编写测试计划、首版测试用例、基线记录和待确认问题
  ↓
等待 B 交付冻结版本
  ↓
阶段二：收到 B 冻结产物后
  ↓
核对 B 的 Commit、接口说明、变更清单和自测结果
  ↓
在 C 固化的数据库环境上执行冒烟测试
  ↓
执行功能、异常、权限和集成测试
  ↓
登记缺陷并反馈给对应负责人
  ↓
获取修复版本并回归测试
  ↓
生成最终测试报告、用户手册和演示脚本
  ↓
给出最终测试结论并归档证据
```

阶段判断规则：

- 如果 B 尚未提供明确的待测 Commit、接口/异常说明和自测结果，Agent 只能执行阶段一；
- 如果 B 明确说明“后端无代码变更”，但提供了冻结 Commit、当前实现说明、已知问题和自测结果，可进入阶段二；
- 如果 B 只口头说“完成了”，却没有版本号和说明文档，不视为正式交付；
- 阶段二只能测试一个明确的冻结版本，禁止混用不同分支或不同 Commit 的结果。

### D1-05：编写完整首版测试用例

Agent 应至少编写以下测试集：

#### 功能测试

- 正常采购入库；
- FIFO 出库；
- LIFO 出库；
- 正常盘点；
- 正常调拨；
- 库存查询；
- 库存预警；
- 统计报表。

#### 异常与边界测试

- 必填参数为空；
- 数量为 0；
- 数量为负数；
- 库存不足；
- 不存在或无效的货品；
- 源仓和目标仓相同；
- 调拨库存不足；
- 盘点数量为负数；
- 错误用户名或密码；
- 重复提交同一表单。

#### 权限测试

- 未登录访问受限页面；
- 采购人员尝试访问非授权功能；
- 领料人员尝试访问非授权功能；
- 仓库管理员执行合法库存业务；
- 系统管理员访问管理功能；
- 页面隐藏按钮后直接构造请求，验证后端是否仍会拒绝越权操作。

#### 集成与一致性测试

- 页面提交后，后端提示与数据库结果一致；
- 入库后库存、批次和流水一致；
- 出库后库存、成本和单据一致；
- 库存不足失败后数据库无部分写入；
- 调拨成功时源仓减少、目标仓增加；
- 调拨失败时两个仓库均不变化；
- 盘点后账面数量、差异记录和预警一致。

每条测试用例必须包含：

| 字段 | 要求 |
|---|---|
| 用例编号 | 唯一，例如 `OUT-FIFO-001` |
| 关联需求 | FR-01～FR-06 中至少一项 |
| 测试类型 | 功能/异常/权限/集成/回归/易用性 |
| 前置条件 | 账号、初始库存、数据库状态、版本号 |
| 测试数据 | 明确的货品、仓库、数量和单价 |
| 操作步骤 | 可由其他人重复执行 |
| 预期结果 | 页面、接口和数据库三个层面的预期 |
| 实际结果 | 阶段一未执行时填“待执行” |
| 证据编号 | 截图、日志或 SQL 结果编号 |
| 结果 | 通过/失败/阻塞/未执行 |

### D2-02：执行交付物完整性检查

Agent 对 B 的交付进行检查：

- [ ] 模块和调用关系可追踪；
- [ ] 接口路径、参数和返回结果明确；

缺失项登记到缺陷/阻塞清单，不得自行猜测。

### D2-03：验证环境和执行冒烟测试

按照 `C → B → D` 的集成顺序：

1. 等待 C 确认数据库环境和脚本版本；
2. 等待 B 确认后端启动成功且核心入口可访问；
3. D 再开始页面联调和冒烟测试；
4. 重跑 BASE-001～BASE-010；
5. 若冒烟测试存在阻塞缺陷，暂停大规模测试并立即反馈。

冒烟测试通过条件：

- 登录可用；
- 入库、出库、盘点、调拨页面可访问；
- 页面可以读取数据库基础数据；
- 至少一条核心业务请求可以正常提交；
- 无阻塞级启动、连接或路由问题。

### D2-04：执行功能与异常测试

按以下顺序执行，避免数据相互污染：

1. 登录与权限；
2. 采购入库；
3. FIFO 出库；
4. LIFO 出库；
5. 库存不足与参数错误；
6. 库存盘点；
7. 仓库调拨；
8. 库存查询和预警；
9. 统计报表；
10. 易用性与页面提示。

FIFO/LIFO 推荐测试数据仅在 C 确认测试环境可重置后使用：

| 场景 | 测试数据 | 预期结果 |
|---|---|---|
| FIFO | 同一货品先入库 100×5，再入库 50×6，出库 120 | 成本为 620，剩余 30×6 |
| LIFO | 同一货品先入库 100×5，再入库 50×6，出库 120 | 成本为 650，剩余 30×5 |
| 库存不足 | 当前可用库存小于请求出库数量 | 请求失败，库存、批次和单据不发生部分写入 |
| 调拨失败 | 源仓库存小于调拨数量 | 源仓和目标仓均不变化 |
| 盘点异常 | 实盘数量为负数 | 请求被拒绝，不写入盘点修正 |

每次业务测试都必须同时检查：

- 页面提示；
- 后端日志或返回状态；
- 数据库最终结果；
- 是否出现部分写入；
- 是否产生正确的预警或统计变化。

### D2-05：执行权限测试

Agent 应依据 A 的最终权限矩阵测试：

1. 未登录用户直接访问受限 URL；
2. 采购人员访问采购允许功能；
3. 采购人员尝试访问盘点、调拨或其他受限功能；
4. 领料人员访问允许功能并尝试越权；
5. 仓库管理员执行库存业务；
6. 系统管理员访问管理功能；
7. 隐藏前端按钮后直接构造 POST 请求，确认后端仍会拒绝越权操作；
8. 退出登录后旧页面或旧请求不可继续执行。

如果权限功能尚未实现，相关用例必须标记为“失败”或“阻塞”，不能标记为“通过”。

### D2-06：登记和分派缺陷

每个缺陷必须包含：

| 字段 | 要求 |
|---|---|
| 缺陷编号 | 例如 `BUG-B-001`、`BUG-C-001`、`BUG-D-001` |
| 发现版本 | Commit SHA |
| 关联用例 | 测试用例编号 |
| 严重程度 | S1 阻塞、S2 严重、S3 一般、S4 轻微 |
| 前置条件 | 账号、数据库状态和数据 |
| 复现步骤 | 可以重复执行 |
| 预期结果 | 依据需求或设计 |
| 实际结果 | 客观描述，不写推测原因 |
| 证据 | 截图、日志、SQL 查询结果 |
| 责任人 | A/B/C/D |
| 状态 | 新建、处理中、待复测、已关闭、延期 |
| 复测结果 | 修复版本和验证结论 |

严重程度定义：

- **S1 阻塞**：系统无法启动、无法登录、数据库无法连接、核心流程完全不可测；
- **S2 严重**：库存错误、事务未回滚、越权成功、核心业务结果错误；
- **S3 一般**：非核心流程错误、提示不正确但有替代方式；
- **S4 轻微**：样式、排版、文案或不影响操作的问题。

### D2-07：获取修复并执行回归测试

收到修复后，Agent 必须：

1. 记录修复 Commit；
2. 先重跑原失败用例；
3. 再运行被修改模块的正常场景；
4. 回归共享 Service、Mapper 或异常处理的关联场景；
5. 至少重跑一条完整核心业务流程；
6. 更新缺陷状态和复测证据；
7. 不得仅根据开发者“已修复”的口头说明关闭缺陷。

### D2-08：执行最终演示验证

Agent 使用冻结版本，从干净测试环境依次演示：

1. 登录和权限；
2. 采购入库；
3. FIFO/LIFO 出库；
4. 库存不足失败且数据不变；
5. 库存盘点；
6. 仓库调拨；
7. 库存查询与预警；
8. 统计报表。

演示过程中不得临时修改数据库或代码。若必须手工修正数据，说明测试环境尚未达到发布条件。
