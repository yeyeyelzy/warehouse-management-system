## 一、数据库高级对象概述

本设计在关系表结构（阶段三）之上，综合运用了 MySQL 8.0 的四类高级数据库对象，实现数据自动联动、业务逻辑封装与数据一致性保障：

| 对象类型 | 数量 | 作用 |
| --- | --- | --- |
| 视图（View） | 4 个 | 封装常用统计查询，简化前端与二次开发 |
| 触发器（Trigger） | 8 个 | 库存自动联动、审核扣减、预警生成、删除修改回滚 |
| 存储过程（Procedure） | 4 个 | 封装入库、FIFO/LIFO 出库成本核算、盘点、调拨业务，内置事务 |
| 事务（Transaction） | 贯穿所有存储过程 | 保证高风险业务（退货、盘点、调拨、成本核算）的原子性与一致性 |

四类对象协同关系：**存储过程**负责复杂业务编排与事务控制，**触发器**负责库存/预警的自动联动，**视图**负责查询封装，**事务**保证异常时可整体回滚。

## 二、视图设计与实现

### 2.1 当前实时库存视图 v_stock_overview

业务用途：实时库存总览，展示货品、分类、仓库、当前库存数量、库存占用资金、上下限阈值、计价方式及实时库存状态（NORMAL 正常 / LOW 低于下限 / OVER 高于上限）。

```sql
DROP VIEW IF EXISTS v_stock_overview;
CREATE VIEW v_stock_overview AS
SELECT
    s.stock_id,
    g.goods_code,
    g.goods_name,
    g.spec,
    g.unit,
    c.category_name,
    w.warehouse_id,
    w.warehouse_name,
    s.quantity AS stock_quantity,
    s.total_cost AS occupied_cost,
    g.lower_limit,
    g.upper_limit,
    g.cost_method,
    CASE
        WHEN s.quantity < g.lower_limit THEN 'LOW'
        WHEN s.quantity > g.upper_limit THEN 'OVER'
        ELSE 'NORMAL'
    END AS stock_status
FROM stock s
JOIN goods g ON s.goods_id = g.goods_id
JOIN warehouse w ON s.warehouse_id = w.warehouse_id
LEFT JOIN goods_category c ON g.category_id = c.category_id;
```

### 2.2 超储/短缺预警货品视图 v_stock_warning

业务用途：实时筛选超储（高于上限）与短缺（低于下限）的货品，输出预警类型与超出/缺口数量，供补货或促销决策。

```sql
DROP VIEW IF EXISTS v_stock_warning;
CREATE VIEW v_stock_warning AS
SELECT
    s.stock_id,
    g.goods_code,
    g.goods_name,
    g.spec,
    g.unit,
    w.warehouse_name,
    s.quantity AS current_quantity,
    g.lower_limit,
    g.upper_limit,
    CASE
        WHEN s.quantity < g.lower_limit THEN 'LOW'
        WHEN s.quantity > g.upper_limit THEN 'OVER'
    END AS warn_type,
    CASE
        WHEN s.quantity < g.lower_limit THEN g.lower_limit - s.quantity
        WHEN s.quantity > g.upper_limit THEN s.quantity - g.upper_limit
        ELSE 0
    END AS warn_quantity
FROM stock s
JOIN goods g ON s.goods_id = g.goods_id
JOIN warehouse w ON s.warehouse_id = w.warehouse_id
WHERE s.quantity < g.lower_limit OR s.quantity > g.upper_limit;
```

### 2.3 出入库明细汇总视图 v_inout_summary

业务用途：将入库与出库明细合并为统一视图，用 `flow_type`（IN/OUT）区分方向。出库行的 `unit_cost`/`total_cost` 即 FIFO/LIFO 计算出的成本，支持按货品、计价方式、时间段查询成本。

```sql
DROP VIEW IF EXISTS v_inout_summary;
CREATE VIEW v_inout_summary AS
SELECT
    'IN' AS flow_type,
    io.order_no,
    io.biz_type,
    io.inbound_date AS flow_date,
    w.warehouse_name,
    g.goods_code,
    g.goods_name,
    g.cost_method,
    ii.quantity,
    ii.unit_price,
    ii.amount,
    CAST(NULL AS DECIMAL(12,2)) AS unit_cost,
    CAST(NULL AS DECIMAL(12,2)) AS total_cost
FROM inbound_order io
JOIN inbound_item ii ON io.inbound_id = ii.inbound_id
JOIN goods g ON ii.goods_id = g.goods_id
JOIN warehouse w ON io.warehouse_id = w.warehouse_id
UNION ALL
SELECT
    'OUT' AS flow_type,
    oo.order_no,
    oo.biz_type,
    oo.outbound_date AS flow_date,
    w.warehouse_name,
    g.goods_code,
    g.goods_name,
    g.cost_method,
    oi.quantity,
    CAST(NULL AS DECIMAL(12,2)) AS unit_price,
    CAST(NULL AS DECIMAL(12,2)) AS amount,
    oi.unit_cost,
    oi.total_cost
FROM outbound_order oo
JOIN outbound_item oi ON oo.outbound_id = oi.outbound_id
JOIN goods g ON oi.goods_id = g.goods_id
JOIN warehouse w ON oo.warehouse_id = w.warehouse_id;
```

### 2.4 FIFO/LIFO 成本批次视图 v_stock_batch_cost

业务用途：展示各成本批次剩余数量、单位成本、剩余成本与入库日期，支撑 FIFO（`inbound_date` 升序扣减）、LIFO（降序扣减）出库成本核算查询。

```sql
DROP VIEW IF EXISTS v_stock_batch_cost;
CREATE VIEW v_stock_batch_cost AS
SELECT
    b.batch_id,
    b.batch_no,
    b.warehouse_id,
    w.warehouse_name,
    b.goods_id,
    g.goods_code,
    g.goods_name,
    g.cost_method,
    b.quantity AS remain_quantity,
    b.unit_cost,
    ROUND(b.quantity * b.unit_cost, 2) AS remain_cost,
    b.inbound_date
FROM stock_batch b
JOIN goods g ON b.goods_id = g.goods_id
JOIN warehouse w ON b.warehouse_id = w.warehouse_id;
```

## 三、触发器设计与实现

触发器共 8 个对象，对应 4 项功能需求，统一使用 AFTER 触发时机，保证库存数据联动一致。触发器仅做库存数量/占用资金/预警的机械联动，不实现 FIFO/LIFO 成本核算与批次维护（由存储过程负责，避免重复）。

### 3.1 功能① 入库明细插入后自动累加库存

```sql
CREATE TRIGGER trg_inbound_item_after_insert
AFTER INSERT ON inbound_item
FOR EACH ROW
BEGIN
    DECLARE v_warehouse_id INT UNSIGNED;
    SELECT warehouse_id INTO v_warehouse_id FROM inbound_order WHERE inbound_id = NEW.inbound_id;
    INSERT INTO stock (warehouse_id, goods_id, quantity, total_cost)
    VALUES (v_warehouse_id, NEW.goods_id, NEW.quantity, NEW.amount)
    ON DUPLICATE KEY UPDATE
        quantity = quantity + NEW.quantity,
        total_cost = total_cost + NEW.amount;
END;
```

### 3.2 功能② 出库单审核通过后自动扣减库存

出库单状态由「非已审核」变更为「已审核(1)」时，用游标遍历该单全部明细扣减库存。

```sql
CREATE TRIGGER trg_outbound_order_after_approve
AFTER UPDATE ON outbound_order
FOR EACH ROW
BEGIN
    DECLARE v_goods_id INT UNSIGNED;
    DECLARE v_quantity DECIMAL(12,2);
    DECLARE v_total_cost DECIMAL(12,2);
    DECLARE done INT DEFAULT 0;
    DECLARE cur CURSOR FOR
        SELECT goods_id, quantity, total_cost FROM outbound_item WHERE outbound_id = NEW.outbound_id;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;

    IF NEW.status = 1 AND OLD.status <> 1 THEN
        OPEN cur;
        read_loop: LOOP
            FETCH cur INTO v_goods_id, v_quantity, v_total_cost;
            IF done = 1 THEN LEAVE read_loop; END IF;
            UPDATE stock
            SET quantity = quantity - v_quantity, total_cost = total_cost - v_total_cost
            WHERE warehouse_id = NEW.warehouse_id AND goods_id = v_goods_id;
        END LOOP;
        CLOSE cur;
    END IF;
END;
```

### 3.3 功能③ 库存上下限预警（新增）

库存新增或数量变动后，低于下限写 LOW 预警、高于上限写 OVER 预警。

```sql
-- 库存新增后判断
CREATE TRIGGER trg_stock_after_insert
AFTER INSERT ON stock
FOR EACH ROW
BEGIN
    DECLARE v_lower DECIMAL(12,2);
    DECLARE v_upper DECIMAL(12,2);
    SELECT lower_limit, upper_limit INTO v_lower, v_upper FROM goods WHERE goods_id = NEW.goods_id;
    IF NEW.quantity < v_lower THEN
        INSERT INTO stock_alert (goods_id, warehouse_id, alert_type, current_quantity, threshold, alert_time, status)
        VALUES (NEW.goods_id, NEW.warehouse_id, 'LOW', NEW.quantity, v_lower, NOW(), 0);
    ELSEIF NEW.quantity > v_upper THEN
        INSERT INTO stock_alert (goods_id, warehouse_id, alert_type, current_quantity, threshold, alert_time, status)
        VALUES (NEW.goods_id, NEW.warehouse_id, 'OVER', NEW.quantity, v_upper, NOW(), 0);
    END IF;
END;

-- 库存数量变动后判断
CREATE TRIGGER trg_stock_after_update
AFTER UPDATE ON stock
FOR EACH ROW
BEGIN
    DECLARE v_lower DECIMAL(12,2);
    DECLARE v_upper DECIMAL(12,2);
    IF NEW.quantity <> OLD.quantity THEN
        SELECT lower_limit, upper_limit INTO v_lower, v_upper FROM goods WHERE goods_id = NEW.goods_id;
        IF NEW.quantity < v_lower THEN
            INSERT INTO stock_alert (goods_id, warehouse_id, alert_type, current_quantity, threshold, alert_time, status)
            VALUES (NEW.goods_id, NEW.warehouse_id, 'LOW', NEW.quantity, v_lower, NOW(), 0);
        ELSEIF NEW.quantity > v_upper THEN
            INSERT INTO stock_alert (goods_id, warehouse_id, alert_type, current_quantity, threshold, alert_time, status)
            VALUES (NEW.goods_id, NEW.warehouse_id, 'OVER', NEW.quantity, v_upper, NOW(), 0);
        END IF;
    END IF;
END;
```

### 3.4 功能④ 单据删除/修改反向回滚库存（新增）

入库/出库明细执行删除或修改数量时，自动反向回滚调整库存。

| 触发器 | 时机 | 逻辑 |
| --- | --- | --- |
| trg_inbound_item_after_delete | DELETE 入库明细 | 回减数量/金额 |
| trg_inbound_item_after_update | UPDATE 入库明细 | 按差值(新-旧)调整 |
| trg_outbound_item_after_delete | DELETE 出库明细 | 已审核时回增数量/成本 |
| trg_outbound_item_after_update | UPDATE 出库明细 | 已审核时按差值(旧-新)调整 |

```sql
-- 入库明细删除 -> 反向回滚
CREATE TRIGGER trg_inbound_item_after_delete
AFTER DELETE ON inbound_item
FOR EACH ROW
BEGIN
    DECLARE v_warehouse_id INT UNSIGNED;
    SELECT warehouse_id INTO v_warehouse_id FROM inbound_order WHERE inbound_id = OLD.inbound_id;
    UPDATE stock SET quantity = quantity - OLD.quantity, total_cost = total_cost - OLD.amount
    WHERE warehouse_id = v_warehouse_id AND goods_id = OLD.goods_id;
END;

-- 入库明细修改 -> 反向回滚
CREATE TRIGGER trg_inbound_item_after_update
AFTER UPDATE ON inbound_item
FOR EACH ROW
BEGIN
    DECLARE v_warehouse_id INT UNSIGNED;
    IF NEW.quantity <> OLD.quantity OR NEW.amount <> OLD.amount THEN
        SELECT warehouse_id INTO v_warehouse_id FROM inbound_order WHERE inbound_id = NEW.inbound_id;
        UPDATE stock SET quantity = quantity + (NEW.quantity - OLD.quantity), total_cost = total_cost + (NEW.amount - OLD.amount)
        WHERE warehouse_id = v_warehouse_id AND goods_id = NEW.goods_id;
    END IF;
END;

-- 出库明细删除 -> 反向回滚（仅已审核）
CREATE TRIGGER trg_outbound_item_after_delete
AFTER DELETE ON outbound_item
FOR EACH ROW
BEGIN
    DECLARE v_warehouse_id INT UNSIGNED;
    DECLARE v_status TINYINT;
    SELECT warehouse_id, status INTO v_warehouse_id, v_status FROM outbound_order WHERE outbound_id = OLD.outbound_id;
    IF v_status = 1 THEN
        UPDATE stock SET quantity = quantity + OLD.quantity, total_cost = total_cost + OLD.total_cost
        WHERE warehouse_id = v_warehouse_id AND goods_id = OLD.goods_id;
    END IF;
END;

-- 出库明细修改 -> 反向回滚（仅已审核）
CREATE TRIGGER trg_outbound_item_after_update
AFTER UPDATE ON outbound_item
FOR EACH ROW
BEGIN
    DECLARE v_warehouse_id INT UNSIGNED;
    DECLARE v_status TINYINT;
    IF NEW.quantity <> OLD.quantity OR NEW.total_cost <> OLD.total_cost THEN
        SELECT warehouse_id, status INTO v_warehouse_id, v_status FROM outbound_order WHERE outbound_id = NEW.outbound_id;
        IF v_status = 1 THEN
            UPDATE stock SET quantity = quantity + (OLD.quantity - NEW.quantity), total_cost = total_cost + (OLD.total_cost - NEW.total_cost)
            WHERE warehouse_id = v_warehouse_id AND goods_id = NEW.goods_id;
        END IF;
    END IF;
END;
```

## 四、存储过程设计与实现

共 4 个存储过程，全部内置事务、SQLEXCEPTION 异常捕获与回滚，统一使用 OUT 参数 `p_status_code`（0 成功/1 失败）与 `p_status_msg` 返回结果。

### 4.1 货品入库存储过程 sp_inbound

业务流程：校验数量 → 新增入库单主表（status=1）→ 写入库明细（触发器自动累加库存）→ 写入成本批次（供 FIFO/LIFO 核算）。

```sql
CREATE PROCEDURE sp_inbound(
    IN  p_warehouse_id INT UNSIGNED, IN p_goods_id INT UNSIGNED,
    IN  p_quantity DECIMAL(12,2), IN p_unit_price DECIMAL(12,2),
    IN  p_operator_id INT UNSIGNED, IN p_supplier_id INT UNSIGNED,
    IN  p_biz_type VARCHAR(20),
    OUT p_status_code INT, OUT p_status_msg VARCHAR(255)
)
BEGIN
    DECLARE v_inbound_id INT UNSIGNED;
    DECLARE v_item_id INT UNSIGNED;
    DECLARE v_order_no VARCHAR(50);
    DECLARE v_amount DECIMAL(12,2);
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        GET DIAGNOSTICS CONDITION 1 p_status_msg = MESSAGE_TEXT;
        ROLLBACK;
        SET p_status_code = 1;
    END;

    START TRANSACTION;
    IF p_quantity IS NULL OR p_quantity <= 0 THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '入库数量必须大于0';
    END IF;
    SET v_amount = p_quantity * p_unit_price;
    SET v_order_no = CONCAT('IN', DATE_FORMAT(NOW(6), '%Y%m%d%H%i%s%f'));

    INSERT INTO inbound_order (order_no, biz_type, warehouse_id, supplier_id, operator_id, total_amount, status)
    VALUES (v_order_no, p_biz_type, p_warehouse_id, p_supplier_id, p_operator_id, v_amount, 1);
    SET v_inbound_id = LAST_INSERT_ID();

    INSERT INTO inbound_item (inbound_id, goods_id, quantity, unit_price, amount)
    VALUES (v_inbound_id, p_goods_id, p_quantity, p_unit_price, v_amount);
    SET v_item_id = LAST_INSERT_ID();

    INSERT INTO stock_batch (warehouse_id, goods_id, inbound_item_id, batch_no, quantity, unit_cost, inbound_date)
    VALUES (p_warehouse_id, p_goods_id, v_item_id, v_order_no, p_quantity, p_unit_price, CURDATE());

    COMMIT;
    SET p_status_code = 0;
    SET p_status_msg = CONCAT('入库成功，入库单号：', v_order_no);
END;
```

### 4.2 出库成本核算存储过程 sp_outbound_cost（FIFO/LIFO）

#### FIFO/LIFO 成本核算原理

1. 读取货品 `cost_method` 计价方式；
2. 校验批次总可用量 ≥ 出库量，否则报“库存不足”；
3. 用游标遍历成本批次：**FIFO 按入库日期升序扣减（先进先出），LIFO 按降序扣减（后进先出）**；
4. 逐批扣减剩余数量，累加 `出库总成本 = Σ(本次扣减量 × 批次单价)`；
5. `单位成本 = 出库总成本 / 出库量`，写入出库明细，审核通过后由触发器扣减库存。

```sql
CREATE PROCEDURE sp_outbound_cost(
    IN  p_warehouse_id INT UNSIGNED, IN p_goods_id INT UNSIGNED,
    IN  p_quantity DECIMAL(12,2), IN p_operator_id INT UNSIGNED,
    IN  p_biz_type VARCHAR(20),
    OUT p_status_code INT, OUT p_status_msg VARCHAR(255), OUT p_out_total_cost DECIMAL(12,2)
)
BEGIN
    DECLARE v_cost_method VARCHAR(10);
    DECLARE v_available DECIMAL(12,2);
    DECLARE v_order_no VARCHAR(50);
    DECLARE v_outbound_id INT UNSIGNED;
    DECLARE v_remain DECIMAL(12,2);
    DECLARE v_batch_id INT UNSIGNED;
    DECLARE v_batch_qty DECIMAL(12,2);
    DECLARE v_batch_cost DECIMAL(12,2);
    DECLARE v_use_qty DECIMAL(12,2);
    DECLARE v_total_cost DECIMAL(12,2) DEFAULT 0;
    DECLARE v_unit_cost DECIMAL(12,2);
    DECLARE v_is_lifo TINYINT DEFAULT 0;
    DECLARE done INT DEFAULT 0;

    DECLARE cur_fifo CURSOR FOR
        SELECT batch_id, quantity, unit_cost FROM stock_batch
        WHERE warehouse_id = p_warehouse_id AND goods_id = p_goods_id AND quantity > 0
        ORDER BY inbound_date ASC, batch_id ASC;

    DECLARE cur_lifo CURSOR FOR
        SELECT batch_id, quantity, unit_cost FROM stock_batch
        WHERE warehouse_id = p_warehouse_id AND goods_id = p_goods_id AND quantity > 0
        ORDER BY inbound_date DESC, batch_id DESC;

    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        GET DIAGNOSTICS CONDITION 1 p_status_msg = MESSAGE_TEXT;
        ROLLBACK;
        SET p_status_code = 1;
    END;

    START TRANSACTION;
    IF p_quantity IS NULL OR p_quantity <= 0 THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '出库数量必须大于0';
    END IF;

    SELECT cost_method INTO v_cost_method FROM goods WHERE goods_id = p_goods_id;
    IF v_cost_method = 'LIFO' THEN SET v_is_lifo = 1; END IF;

    SELECT COALESCE(SUM(quantity), 0) INTO v_available
    FROM stock_batch
    WHERE warehouse_id = p_warehouse_id AND goods_id = p_goods_id AND quantity > 0;
    IF v_available < p_quantity THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '库存不足，无法出库';
    END IF;

    SET v_remain = p_quantity;
    SET v_total_cost = 0;

    IF v_is_lifo = 1 THEN OPEN cur_lifo; ELSE OPEN cur_fifo; END IF;

    read_loop: LOOP
        IF v_is_lifo = 1 THEN FETCH cur_lifo INTO v_batch_id, v_batch_qty, v_batch_cost;
        ELSE FETCH cur_fifo INTO v_batch_id, v_batch_qty, v_batch_cost; END IF;
        IF done = 1 THEN LEAVE read_loop; END IF;

        IF v_batch_qty >= v_remain THEN SET v_use_qty = v_remain; ELSE SET v_use_qty = v_batch_qty; END IF;
        SET v_total_cost = v_total_cost + v_use_qty * v_batch_cost;
        SET v_remain = v_remain - v_use_qty;

        UPDATE stock_batch SET quantity = quantity - v_use_qty WHERE batch_id = v_batch_id;
        IF v_remain <= 0 THEN LEAVE read_loop; END IF;
    END LOOP;

    IF v_is_lifo = 1 THEN CLOSE cur_lifo; ELSE CLOSE cur_fifo; END IF;
    IF v_remain > 0 THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '成本批次不足'; END IF;

    SET v_unit_cost = v_total_cost / p_quantity;
    SET v_order_no = CONCAT('OUT', DATE_FORMAT(NOW(6), '%Y%m%d%H%i%s%f'));

    INSERT INTO outbound_order (order_no, biz_type, warehouse_id, operator_id, total_cost, total_amount, status)
    VALUES (v_order_no, p_biz_type, p_warehouse_id, p_operator_id, v_total_cost, 0, 0);
    SET v_outbound_id = LAST_INSERT_ID();

    INSERT INTO outbound_item (outbound_id, goods_id, quantity, unit_cost, total_cost)
    VALUES (v_outbound_id, p_goods_id, p_quantity, v_unit_cost, v_total_cost);

    UPDATE outbound_order SET status = 1 WHERE outbound_id = v_outbound_id;

    COMMIT;
    SET p_status_code = 0;
    SET p_status_msg = CONCAT('出库成功，计价方式=', v_cost_method, '，出库成本=', v_total_cost);
    SET p_out_total_cost = v_total_cost;
END;
```

### 4.3 库存盘点存储过程 sp_stocktake（盘盈盘亏）

业务流程：读取账面数量与占用资金 → 计算差异(实盘-账面)，判定盘盈 GAIN / 盘亏 LOSS / 无差异 NONE → 生成盘点单主表+明细（`stocktake_order`/`stocktake_item`）→ 按平均成本修正库存数量与占用资金。

```sql
CREATE PROCEDURE sp_stocktake(
    IN  p_warehouse_id INT UNSIGNED, IN p_goods_id INT UNSIGNED,
    IN  p_actual_quantity DECIMAL(12,2), IN p_operator_id INT UNSIGNED,
    OUT p_status_code INT, OUT p_status_msg VARCHAR(255)
)
BEGIN
    DECLARE v_book_qty DECIMAL(12,2) DEFAULT 0;
    DECLARE v_total_cost DECIMAL(12,2) DEFAULT 0;
    DECLARE v_avg_cost DECIMAL(12,2) DEFAULT 0;
    DECLARE v_diff DECIMAL(12,2);
    DECLARE v_diff_type VARCHAR(10);
    DECLARE v_stocktake_id INT UNSIGNED;
    DECLARE v_order_no VARCHAR(50);

    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        GET DIAGNOSTICS CONDITION 1 p_status_msg = MESSAGE_TEXT;
        ROLLBACK;
        SET p_status_code = 1;
    END;

    START TRANSACTION;
    IF p_actual_quantity IS NULL OR p_actual_quantity < 0 THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '实盘数量不能为负';
    END IF;

    SET v_book_qty = COALESCE((SELECT quantity FROM stock WHERE warehouse_id = p_warehouse_id AND goods_id = p_goods_id), 0);
    SET v_total_cost = COALESCE((SELECT total_cost FROM stock WHERE warehouse_id = p_warehouse_id AND goods_id = p_goods_id), 0);

    SET v_diff = p_actual_quantity - v_book_qty;
    IF v_diff > 0 THEN SET v_diff_type = 'GAIN';
    ELSEIF v_diff < 0 THEN SET v_diff_type = 'LOSS';
    ELSE SET v_diff_type = 'NONE'; END IF;

    IF v_book_qty > 0 THEN SET v_avg_cost = v_total_cost / v_book_qty;
    ELSE SET v_avg_cost = COALESCE((SELECT price FROM goods WHERE goods_id = p_goods_id), 0); END IF;

    SET v_order_no = CONCAT('ST', DATE_FORMAT(NOW(6), '%Y%m%d%H%i%s%f'));
    INSERT INTO stocktake_order (order_no, warehouse_id, operator_id, status)
    VALUES (v_order_no, p_warehouse_id, p_operator_id, 1);
    SET v_stocktake_id = LAST_INSERT_ID();

    INSERT INTO stocktake_item (stocktake_id, goods_id, book_quantity, actual_quantity, diff_quantity, diff_type)
    VALUES (v_stocktake_id, p_goods_id, v_book_qty, p_actual_quantity, v_diff, v_diff_type);

    INSERT INTO stock (warehouse_id, goods_id, quantity, total_cost)
    VALUES (p_warehouse_id, p_goods_id, p_actual_quantity, p_actual_quantity * v_avg_cost)
    ON DUPLICATE KEY UPDATE
        quantity = p_actual_quantity, total_cost = p_actual_quantity * v_avg_cost;

    COMMIT;
    SET p_status_code = 0;
    SET p_status_msg = CONCAT('盘点完成，差异类型=', v_diff_type, '，差异数量=', v_diff);
END;
```

### 4.4 批量货品调拨存储过程 sp_transfer

业务流程：校验调出≠调入 → 生成调拨单主表 → 用 `JSON_TABLE` 解析明细 JSON 游标 → 逐项校验源仓库存 → 扣源仓数量/占用资金、增目标仓数量/占用资金 → 写调拨明细，全部在同一事务内，任一项失败整体回滚。

```sql
CREATE PROCEDURE sp_transfer(
    IN  p_from_warehouse_id INT UNSIGNED, IN p_to_warehouse_id INT UNSIGNED,
    IN  p_operator_id INT UNSIGNED, IN p_items JSON,
    OUT p_status_code INT, OUT p_status_msg VARCHAR(255)
)
BEGIN
    DECLARE v_transfer_id INT UNSIGNED;
    DECLARE v_order_no VARCHAR(50);
    DECLARE v_goods_id INT UNSIGNED;
    DECLARE v_quantity DECIMAL(12,2);
    DECLARE v_available DECIMAL(12,2);
    DECLARE v_avg_cost DECIMAL(12,2);
    DECLARE done INT DEFAULT 0;

    DECLARE cur CURSOR FOR
        SELECT jt.goods_id, jt.quantity
        FROM JSON_TABLE(p_items, '$[*]' COLUMNS(
            goods_id INT PATH '$.goods_id',
            quantity DECIMAL(12,2) PATH '$.quantity'
        )) AS jt;

    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        GET DIAGNOSTICS CONDITION 1 p_status_msg = MESSAGE_TEXT;
        ROLLBACK;
        SET p_status_code = 1;
    END;

    START TRANSACTION;
    IF p_from_warehouse_id = p_to_warehouse_id THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '调出仓库与调入仓库不能相同';
    END IF;
    IF p_items IS NULL OR JSON_LENGTH(p_items) = 0 THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '调拨明细不能为空';
    END IF;

    SET v_order_no = CONCAT('TR', DATE_FORMAT(NOW(6), '%Y%m%d%H%i%s%f'));
    INSERT INTO transfer_order (order_no, from_warehouse_id, to_warehouse_id, operator_id, status)
    VALUES (v_order_no, p_from_warehouse_id, p_to_warehouse_id, p_operator_id, 1);
    SET v_transfer_id = LAST_INSERT_ID();

    OPEN cur;
    read_loop: LOOP
        FETCH cur INTO v_goods_id, v_quantity;
        IF done = 1 THEN LEAVE read_loop; END IF;
        IF v_quantity IS NULL OR v_quantity <= 0 THEN
            SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '调拨数量必须大于0';
        END IF;

        SET v_available = COALESCE((SELECT quantity FROM stock WHERE warehouse_id = p_from_warehouse_id AND goods_id = v_goods_id), 0);
        IF v_available < v_quantity THEN
            SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '源仓库库存不足，无法调拨';
        END IF;

        SET v_avg_cost = COALESCE((SELECT total_cost / NULLIF(quantity, 0) FROM stock WHERE warehouse_id = p_from_warehouse_id AND goods_id = v_goods_id), 0);

        UPDATE stock SET quantity = quantity - v_quantity, total_cost = total_cost - v_quantity * v_avg_cost
        WHERE warehouse_id = p_from_warehouse_id AND goods_id = v_goods_id;

        INSERT INTO stock (warehouse_id, goods_id, quantity, total_cost)
        VALUES (p_to_warehouse_id, v_goods_id, v_quantity, v_quantity * v_avg_cost)
        ON DUPLICATE KEY UPDATE quantity = quantity + v_quantity, total_cost = total_cost + v_quantity * v_avg_cost;

        INSERT INTO transfer_item (transfer_id, goods_id, quantity) VALUES (v_transfer_id, v_goods_id, v_quantity);
    END LOOP;
    CLOSE cur;

    COMMIT;
    SET p_status_code = 0;
    SET p_status_msg = CONCAT('调拨成功，调拨单号：', v_order_no);
END;
```

## 五、事务与异常处理设计

### 5.1 事务设计

所有存储过程统一采用 `START TRANSACTION` 开启事务、`COMMIT` 提交、`ROLLBACK` 回滚的结构。以下高风险业务必须保证原子性：

| 业务 | 事务必要性 |
| --- | --- |
| 入库 | 入库单主表 + 明细 + 成本批次三者必须同时成功，否则数据不完整 |
| 出库成本核算 | 批次扣减 + 出库单 + 出库明细 + 库存扣减必须一致，失败整体回滚 |
| 盘点 | 盘点单 + 盘点明细 + 库存修正必须同时生效，防止账实不一致 |
| 调拨 | 源仓扣减与目标仓增加必须同时成功，任一失败则整体回滚 |

### 5.2 异常捕获

每个存储过程均声明 `DECLARE EXIT HANDLER FOR SQLEXCEPTION`，通过 `GET DIAGNOSTICS CONDITION 1 p_status_msg = MESSAGE_TEXT` 捕获原始错误信息，执行 `ROLLBACK` 并返回 `p_status_code = 1`。业务规则校验（库存不足、数量非法等）使用 `SIGNAL SQLSTATE '45000'` 抛出，同样被异常处理器捕获并回滚。

### 5.3 触发器的联动一致性

入库库存累加由触发器 `trg_inbound_item_after_insert` 完成，出库库存扣减由触发器 `trg_outbound_order_after_approve` 在审核通过时完成，盘点/调拨由存储过程显式修正/转移库存。存储过程聚焦单据、成本批次与 FIFO/LIFO 成本核算，不重复更新库存，避免双重累加/扣减。
