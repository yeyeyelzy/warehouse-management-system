# C-06 数据库接口与联调记录

联调基线为仓库 `main` 的冻结代码与 `code/sql/` 脚本。联调链路为 Spring MVC 的 `/biz/...` 表单入口，经 `BusinessService`、`ProcedureMapper` 调用 MySQL 存储过程。

## 数据库契约

| 过程 | IN 参数顺序 | OUT 参数顺序 |
|---|---|---|
| `sp_inbound` | 仓库、货品、数量、单价、操作人、供应商、业务类型 | 状态码、消息 |
| `sp_outbound_cost` | 仓库、货品、数量、操作人、业务类型 | 状态码、消息、出库成本 |
| `sp_stocktake` | 仓库、货品、实盘量、操作人 | 状态码、消息 |
| `sp_transfer` | 源仓、目标仓、操作人、JSON 明细数组 | 状态码、消息 |

ID 类型为 `INT UNSIGNED`，数量、单价和核算成本为 `DECIMAL(12,2)`。状态码 0 表示成功，1 表示失败并回滚。出库失败的成本参数为空。调拨 JSON 明细包含 `goods_id` 和 `quantity`。现有页面提交单条明细，批量中途失败用 SQL 直接验证。

## 复核事项

- 入库由明细插入触发库存更新，过程创建对应批次。
- 出库先核对库存与批次，再扣批次、写单据、触发库存扣减。服务层通过 Mapper 读取 OUT 值，失败时抛业务异常，由控制器反馈到页面。
- 调拨和盘点更新成本批次，避免后续出库仍使用旧余额。实现位置见 `code/sql/04_create_procedures.sql`。
- 数据库契约由 B 的接口说明、D 的测试计划共同引用；最终可运行后端只保留在 `code/src/`。

| 入口 | 实测结果 |
|---|---|
| 登录与正常入库、出库 | 成功。20 件以单价 5 元入库，出库 2 件显示成本 10.00 元。 |
| FR-04 正常盘点 | 盘盈成功，页面显示 GAIN。 |

| 库存不足、负数盘点、调拨不足 | 三个页面均显示对应错误。目标仓仍为 4 件、源仓仍为 14 件，两仓批次余额与账面相符，单据数量不变。 |

SQL 独立跑了两轮，每轮 15 个演示调用成功、18 项回归断言通过、07 返回零条异常。批量调拨的第二条明细失败时，第一条已执行的库存、批次与预警写入和调拨单一起回滚。最终测试摘要见 `docs/D/09-测试报告.md`。

## 成本边界回归

负单价入库返回失败，单据、库存和成本批次均未写入。用单价 0.50 元入库 0.04 件，分三次各出库 0.01 件后，共结转 0.02 元，剩余 0.01 件成本为 0.00 元。最后一次出库后，批次余额和剩余成本归零。另测小数调拨，两仓分摊金额之和等于调拨前源仓金额。用例编号 C14 至 C18。

## 多连接并发复查

在 MySQL 8.4.10 隔离库完成 18 项 SQL 回归后，使用独立连接同时发起请求。5 组竞争出库均只成功一笔，每组剩余 3 件、成本 6.00 元。5 组反向调拨也均只成功一笔，每组两仓合计仍为 20 件、成本 40.00 元，且各保留一条成功的调拨明细。8 个并发入库请求均成功，最终库存为 8 件、成本 16.00 元。并发用例结束后，07 返回零条异常。

反向调拨存在并发锁冲突时，失败方会回滚整笔操作。应用目前将失败返回给调用方，由调用方决定是否重试。以上结果覆盖所列场景，未执行持续负载测试。
