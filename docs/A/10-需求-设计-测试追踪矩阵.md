# 仓库管理系统 需求-设计-测试追踪矩阵（RTM）

## 1 说明

### 1.1 目的

本矩阵建立**需求（FR/NFR）→ 设计（架构、模块、数据库对象）→ 代码/脚本 → 测试用例 → 结论**的双向可追溯关系，用于：

1. 证明每条需求都被实现且被验证（前向覆盖）；
2. 证明每个设计单元与每个测试用例都有需求来源（反向覆盖，杜绝镀金设计）；
3. 在变更发生时快速定位需重跑的范围（影响分析）。

### 1.2 使用方法

- 横向阅读第 4 章主矩阵：按需求查设计、查代码、查用例。
- 纵向阅读第 6 章用例明细：按编号执行，记录实测结果。
- 状态列取值：`通过` / `部分通过` / `待执行` / `未覆盖`。
- 任何需求变更须同步更新本矩阵对应行与状态，作为基线更新的一部分（见《03-配置管理计划》§6）。

### 1.3 编号规则

| 前缀 | 含义 | 格式示例 |
| --- | --- | --- |
| FR | 功能需求 | FR-01、FR-01-04 |
| NFR | 非功能需求 | NFR-03 |
| UC | 用例 | UC-05 |
| DES | 设计单元（分层模块或数据库对象） | DES-SVC-02、DES-DB-07 |
| TC | 测试用例 | TC-AUTH-03、TC-OUT-02 |
| AC | 验收准则 | AC-04 |
